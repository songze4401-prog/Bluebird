4. **真机未验证**：UI 验收全部来自 Expo Web + jest/RNTL。Web 绿灯不等于 iOS/Android 行为一致。
5. **`project` 作用域缺实体**：`tests/p3-acceptance.test.js` 的 project scope 行是 `skipped`（系统里没有 Project 实体），项目级隔离尚未真正实现。

## 4. 硬约束（违反就出事故）

- **单进程**：`server/data/` 一次性读入内存并整体重写，`server/single-instance.js` 用 `<DATA_DIR>/.bluebird.lock` 在启动时强制；同数据目录起两个实例会互相覆盖（实测并发只剩 14/30）。`BLUEBIRD_ALLOW_MULTI=1` 只是逃生阀，不是并发支持。
- **测试绝不碰 `server/data/`**：实测 72 个 `tests/*.test.js` 里有 66 个把 `BLUEBIRD_DATA_DIR` 指到系统临时目录；其余 6 个以别的方式隔离——`reply-segmentation`、`sticker-markers`、`streaming-segments`、`memory-state-units` 是纯函数且不 require 任何 `server/` 模块，`atomic-write` 与 `monitoring` 各自 `fs.mkdtempSync` 自建临时目录（`monitoring.test.js:23` 把 `dataDir` 显式传给监控模块，而不是设环境变量）。`AGENTS.md` 的「Every tests/*.test.js file points BLUEBIRD_DATA_DIR at an OS temp directory」是概括说法，按实测口径理解，不要去「修正」那 6 个文件。且 `BLUEBIRD_DATA_DIR` **必须在 `require` 任何 `server/` 模块之前设置**（数据路径在模块加载时解析一次，设晚了会静默落回真实目录）。
- **测试里禁 LLM 用 `process.env.DEEPSEEK_API_KEY = ''`，不要 `delete`**：`dotenv` 只补空缺键，`delete` 会在加载 `server/index.js` 时被 `.env` 重新注入，从而发真实请求、产生真实费用。
- **网络层只有一个出口**：`lib/api/client.ts` 的 `apiFetch` 是唯一调 `fetch` 的地方；`App.tsx` 与 `components/**` 里出现 `fetch(...)` 会被 ESLint 以 `error` 拦下。路径只在 `lib/api/endpoints.ts` 拼。
- **`App.tsx` 只做组合与路由（约 300 行）**，聊天逻辑放 `hooks/useChatSession.ts`；`HistoryScreen` 是受控组件，`/sessions` 的唯一来源是 `hooks/useSessionList.ts`。
- **CJS 文本规则边界**：`lib/split-reply.js`、`lib/sticker-markers.js`、`lib/streaming-segments.js` 保持 CommonJS（后端裸 `node`、`node:test`、Metro 三方共用），前端只有 `lib/text-rules.ts` 允许 import 它们。
- **监控只读**：`/monitoring/**` 一律 `requireAuth`，不得新增清理/配置/工具执行端点；事件与 trace 只能是元数据（不含 prompt、记忆文本、工具入参出参、密钥）。
- **`.env` 不是代码改动的一部分**：`.env` 存密钥，按机器配置，改代码时永不编辑或覆盖它。需要新开关就写进 `server/.env.example` 模板。
- **GitHub 令牌只作为 `GH_TOKEN` 环境变量注入**，不回显、不写日志、不提交。
- **Expo 每年破坏式更新**：动 Expo/RN/EAS API 前先读 `package.json` 里 `expo` 主版本，再查 `https://docs.expo.dev/versions/v58.0.0/`，不要凭记忆写。
- **不手写 `ios/`、`android/`**（Continuous Native Generation），原生行为走 `app.json` + config plugins。

## 6. 测试纪律

- **两套 runner 两个目录，不能混**：`tests/*.test.js` 是 `node:test`/自定义运行器（`npm test`、CI）；`tests/unit/**/*.test.ts(x)` 是 jest（`npm run test:unit`，preset `jest-expo`）。`jest.testMatch` 钉死在 `tests/unit/**`。
- **计数只有一个手写源**：`scripts/test-coverage-baseline.json`。`AGENTS.md`、`README.md`、`docs/memory-bot.md`、`docs/unified-retrieval.md`、`docs/observability.md`、`docs/persona-custom-prompt.md` 与 CI 注释里的所有计数由 `node scripts/sync-doc-counts.js` 生成，`--check` 在漂移时让 CI 失败（锚点未命中或命中多次都会显式失败，不会静默跳过）。
- **新增/删除/重数测试文件时，必须在同一个改动里更新**：基线 JSON + `AGENTS.md` + CI 注释（若工作流列了显式文件清单也要一起改）。
- **重数只能靠跑，不能数 `check(`/`test(` 调用点**（运行期计数合法地大于调用点数）。
- **覆盖门禁的性质**：它是精确运行期用例数对账，**不是行覆盖率**，因此发现不了「用例通过但分支未测」。
- **监控默认**：`scripts/run-tests.js` 与 `scripts/verify-test-coverage.js` 设 `BLUEBIRD_MONITORING=0`；监控专项文件自己设回 `1` 并用独立临时目录。
- **隔离自证**：往 `server/data/` 播种哨兵内容 → 跑全量 → 校验文件字节不变。
- **RNTL 14 的 `renderHook` 返回 Promise**，必须 `await`；`act()` 回调不得返回值（否则产生未等待的异步 act）。

## 7. 数据与隐私不变量

- 用户全部数据在 `server/data/`（或 `BLUEBIRD_DATA_DIR`），被 `.gitignore` 排除：**git 里永远没有用户数据**，新克隆是零数据，仓库内没有任何东西能恢复它；备份唯一实现是 `server/backup.js`（CLI `scripts/bluebird-backup.js`，`.sh`/`.ps1` 只是转发包装）。
- `sessions.json` 是权威存储；读坏了进入**就地只读保护**（不重命名、不删除、拒写）。`memory.json`/`emotion-state.json`/`presence.json` 读坏了重命名为 `.corrupt-<ts>` 并用空状态继续——这是**刻意不同**的策略，不要「统一」。
- 所有落盘走 temp+fsync+rename（`writeFileAtomic*`，父目录 fsync 先试 `'r+'` 以兼容 Windows）。
- 删除类操作写墓碑（内容/sourceQuote 哈希 + 贡献的 `messageId`/`sessionId`，绝不含原文），`applyCandidate` 以 `deleted_source` 拒绝同源复活；`duplicate_source` 让自动抽取重试幂等。
- 日志与事件**从不写 `error.message`**（Node 20+ 的 `JSON.parse` 消息会嵌入输入片段，而输入是聊天/记忆正文），只写 `error.name`/`error.code`。
- 画像反馈历史、审计记录、监控 trace 都不含记忆正文、纠正文本、密钥；`reason` 是短码不是自由文本。

## 8. 已知坑（本轮实际踩过，重复成本为零）

- **Git Bash 下 `git show <rev>:<path>` 会被路径转换破坏**：`:` 被改成 `\` 导致 `fatal`，若再 `2>/dev/null` 吞掉错误，`grep -c` 会给出**假阴性 0**。用 `git ls-tree -r <rev> -- <path>` 取 blob 号 + `git cat-file -p <sha>`，或先自检输出非空。
- **Windows 上 `require('server/index.js')` 后直接退出会触发 libuv 断言（exit 127）**：测试脚本需 `Connection: close` + `server.closeAllConnections()` + `await server.close()` + 约 150 ms 让出。
- **`react-hooks/set-state-in-effect` 会被 lint 拦**：详情弹窗的「初始动作」状态不要放在 `useEffect` 里 setState，改为从 props 初始化并把 `initialAction` 放进组件 `key` 触发重挂载。
- **`fetch` 守卫**：新网络调用必须进 `lib/api/client.ts`/`endpoints.ts`，在组件里直接 `fetch` 会以 error 级 lint 失败。
- **改了界面就会打旧测试**：把「未接入操作」换成真实治理入口后，旧断言（`未接入操作/编辑/撤回`）必须同步更新；`buildMemoryOverview` 增加 `contested` 字段、生命周期筛选改名「确认事件」都属此类。
- **动 `scripts/api-capability-registry.json` 后必须重生成 AGENTS 区块**：`node scripts/verify-api-capabilities.js --write`，否则 `AGENTS.md` 的 `<!-- sync:api-capabilities -->` 块与实际登记不一致。
- **情绪测试对磁盘时序敏感**：`happy !== excited` 与 fsync-before-rename 两项在全量运行中出现过瞬时被磁盘拖慢，单跑必过；遇到先单跑确认再判性质。

## 9. 建议推进顺序

按「先补证据缺口、再扩能力」排：

1. **`consumed` 溯源**：这是当前最大的口径缺口——监控页、画像、时间线都在证明「注入了什么」，无法证明「回答实际用了什么」。做法是引入引用标记或后验归因，并在 trace 里区分 `injected` 与 `consumed`，同时把「未采集」的显式状态一路带到 UI（已有先例：Trace 下钻显示「模型实际消费（consumed）：未采集」）。
2. **把 P4 真实腿做成可重复的验收**：目前 4 轮 30/30 是人工记录。把它固化成带密钥的夜间任务（或至少给出可复制的 30 项断言清单），CI 仍不跑真实计费调用。
3. **`project` 实体**：P3 的 project 作用域行是 `skipped`，补一个最小 Project 实体与其归属测试，才能让「项目级记忆/知识隔离」从设计变成事实。
