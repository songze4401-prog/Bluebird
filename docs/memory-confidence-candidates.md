# 记忆证据准入与候选晋升（P2）

本说明记录记忆观察台账之后的证据准入与候选晋升。它只处理已经由现有抽取流程产生的候选，不改变观察器的模式、默认值或调度频率。

## 按类别和证据决定准入

不再用全局 `0.85/0.6` 区间决定所有记忆的写入。策略分别看类别、用户是否直接陈述、原话是否接地、来源可靠性、独立会话数、矛盾/反例、时效、具体度、敏感性、模型置信度和明确的长期意图。证据向量保留这些可解释分量，不把它们压成一个不透明总分。

清晰、具体、近期且没有冲突的用户直述，可按稳定事实、长期偏好或项目决策各自的规则直接成为 active；值得保留但尚不足以自动确定的候选进入 pending；敏感内容、临时状态、过期证据、低效用或来源不足的候选则拒绝。类别候选底线与 active 晋升条件不同，低于 active 条件不等于直接丢弃。偏好可由明确长期意图或独立会话的重复支持加强；strict 模式下，单次偏好先待确认。

候选内容若来自模型推断，必须保留 `model_inferred` provenance 并进入待确认；重复的模型推断不会伪装成用户直述或自动晋升。原话带“可能、也许、似乎、大概、不确定、好像”等犹豫语气时，保留 `source_hedged` 标记和原始 `sourceQuote`，正文不能被改成确定事实；即使跨会话重复，也仍待确认。与已有记忆矛盾时先待确认，只有清晰的用户更正才能按更正路径处理。

候选必须先通过敏感内容检查；`sourceQuote` 经现有文本规范化后必须是用户原话的连续片段；候选正文还必须通过现有内容锚点或关键词接地校验。任一条件不满足，都不会写入候选，也不会记录低置信观察。观察台账仍然只保存内容哈希、会话和短码，不保存正文或原话。

## pending 与检索

符合最低安全和接地要求、但未达到自动 active 条件的候选及其来源贡献写入现有记忆存储，状态为 `pending`，并保留原话、消息 ID、会话 ID、来源类型、provenance 与不确定性标记。pending 条目受既有 20 条容量上限约束，不进入普通有效记忆、检索或上下文注入；它沿用现有待确认记忆管理路径。

## 后续证据如何晋升

只有同一可信用户作用域、相同 provenance 且内容高度相似的候选才会合并。贡献按消息幂等追加；同一会话的重复表达不会被算作独立支持。直接用户陈述可在至少两个独立会话中得到支持，并结合类别、置信度和一致性晋升为 active；记录中保存 `independentSessions` 与可解释的证据分量。冲突或来源不可靠时，重复次数本身不能覆盖这些反证。

模型推断始终保留 `model_inferred` 标记；即使多个会话重复出现，也不会自动晋升。之后出现的用户直述不会改写推断来源，而是作为独立 provenance 处理。

## 撤回、删除与配置边界

撤回或删除会移除相应来源贡献并写入既有墓碑；同一来源消息之后重试时会被墓碑拦截，不能复活候选。观察台账的哈希统计不是晋升依据。

本闭环不改 `BLUEBIRD_MEMORY_OBSERVER` 的当前模式、默认值或抽取频率，不启用 `every_turn`，也不新增配置开关。
