# 低置信记忆候选闭环

本说明记录记忆观察台账之后的最小晋升闭环。它只处理已经由现有观察器抽取出的候选，不改变观察器的模式、默认值或调度频率。

## 哪些候选会被保留

自动抽取的候选只有在置信度为 `0.6 ≤ confidence < 0.85`、没有显式持久化意图，且归入稳定事实、长期偏好、项目决策或模型推断时，才可能进入候选库。更低置信度、临时状态及行为模式继续走拒写/观察路径；显式持久化意图仍沿用既有门槛。

候选必须先通过敏感内容检查；`sourceQuote` 经现有文本规范化后必须是用户原话的连续片段；候选正文还必须通过现有内容锚点或关键词接地校验。任一条件不满足，都不会写入候选，也不会记录低置信观察。观察台账仍然只保存内容哈希、会话和短码，不保存正文或原话。

## pending 与检索

合格候选及其来源贡献写入现有记忆存储，状态为 `pending`，并保留原话、消息 ID、会话 ID、来源类型和 provenance。pending 条目受既有 20 条容量上限约束，不进入普通有效记忆、检索或上下文注入；它沿用现有待确认记忆管理路径。

## 后续证据如何晋升

只有同一可信用户作用域、相同 provenance 且内容高度相似的候选才会合并。贡献按消息幂等追加；同一会话的重复表达不会被算作独立支持。直接用户陈述在至少两个独立会话中得到支持时，可以晋升为 active，并记录 `independentSessions` 与 `independent_support`。高置信度的直接陈述及 strict 偏好的既有规则保持不变。

模型推断始终保留 `model_inferred` 标记；即使多个会话重复出现，也不会自动晋升。之后出现的用户直述不会改写推断来源，而是作为独立 provenance 处理。

## 撤回、删除与配置边界

撤回或删除会移除相应来源贡献并写入既有墓碑；同一来源消息之后重试时会被墓碑拦截，不能复活候选。观察台账的哈希统计不是晋升依据。

本闭环不改 `BLUEBIRD_MEMORY_OBSERVER` 的当前模式、默认值或抽取频率，不启用 `every_turn`，也不新增配置开关。
