## 4. Agent Runtime 架构（改代码前先读这一节）

### 4.1 一条委派任务的完整链路

```
HTTP (server/agents/routes.js)
  → router.decide（路由择一，冻结 planId/planVersion）
  → tasks.createTask（状态 queued，写 task.created 事件）
  → runtime.startTask → 队列 → runtime.runTask
      → acquireLease → fencing.issue（PR #65，代次令牌）
      → transitionTask(accepted) → execute()
          → runAgentTurn（模型循环）
              → 每个工具：tool-gateway 授权（allowedTools → policy → §16 来源链 → 污点）
                         → fail-open 作用域判定（可选）
                         → op-ledger begin（幂等键）→ fencing 校验（PR #65）
                         → circuit-breaker 工具域熔断
                         → handler
              → tool 事件只落工具名/短码/时长，不落参数与返回正文
      → verification-loop（独立评审、trustLevel 只由它写）
      → artifact-commit.persistTaskArtifacts（pending-commit）
      → fencing 再判一次（result_commit）
      → artifact-commit.completeTask（状态与 result 同一次落盘，stateVersion+1）
      → result-delivery.deliverTaskOutcome（回投父会话）
      → finally：releaseLease、终态撤销代次、会话收口
```

### 4.2 关键不变量（改坏了会出事故）

1. **副作用先记账**：有副作用工具必须先 `op-ledger.begin` 落盘（fsync）再执行；`started`/`unknown` 绝不自动重跑，转 recovery 人工核对。
2. **写入资格先于记账**（PR #65）：代次过期/撤销时连意图行都不写，handler 零执行。
3. **fail-closed 优先**：计划读不出、来源链断裂、审批超时、账本不可用，一律拒绝而不是放行；只有明确白名单才放行。
4. **事件白名单双闸**：类型必须在 `tasks.EVENT_TYPES`，payload 键必须在 `SAFE_PAYLOAD_KEYS`；`safePayload` 只收 `null/boolean/string/number`，**数组与对象会被静默丢弃**（列表先 join 成字符串）。
5. **状态机十态**：`queued/accepted/running/retrying/waiting_approval/completed/failed/cancelled/timed_out/recovery`；终态无出边；审批只能从 `running` 进入。
6. **trustLevel 只由验证引擎写**：任务写入路径（`updateTask`/`transitionTask`）写它会留痕并拒绝。
7. **产物两段提交**：pending-commit → committed；任务状态提交失败时产物留在 pending-commit，由启动扫描收敛，不假设跨 Store 原子事务。
8. **单进程**：`server/single-instance.js` 用 `<DATA_DIR>/.bluebird.lock` 强制；`server/data/` 一次性读入内存整体重写，两个实例会互相覆盖。
9. **代次单调**（PR #65）：`agent-fencing.json` 的 counter 只增不减；文件坏了按 `fencing_unavailable` 拒绝，**不要「修复」成 0**。

## 6. 硬约束（违反就出事故）

- **测试绝不碰真实数据目录**：`BLUEBIRD_DATA_DIR` 必须在 `require` 任何 `server/` 模块**之前**指到临时目录（路径在模块加载时解析一次，设晚了会静默落回真实目录）。
- **测试禁 LLM 用 `process.env.DEEPSEEK_API_KEY = ''`，不要 `delete`**：`.env` 会把删掉的键重新注入，导致真实计费调用。
- **`.env` 不是代码改动的一部分**：永不编辑或覆盖；新开关写进 `server/.env.example`。
- **GitHub 令牌只作为 `GH_TOKEN` 环境变量注入**，不回显、不写日志、不提交。
- **网络层只有一个出口**：`lib/api/client.ts` 的 `apiFetch`；组件里直接 `fetch` 会被 ESLint 拦。
- **CJS 文本规则边界**：`lib/split-reply.js`、`lib/sticker-markers.js`、`lib/streaming-segments.js` 保持 CommonJS，前端只有 `lib/text-rules.ts` 可 import。
- **监控只读**：`/monitoring/**` 一律 `requireAuth`，事件与 trace 只能是元数据。
- **不手写 `ios/`、`android/`**（CNG）；Expo 动版本前先读 `package.json` 主版本与对应官方文档。
- **计数只有一个源**：`scripts/test-coverage-baseline.json`，改完跑 `sync-doc-counts.js`，不要手改文档数字。
- **规则表改内容必须升版本**：失败模式处置表改了就升 `failure-modes-vN`（当前 v2，PR #65 引入），阈值表同理。

## 7. 测试与门禁纪律

- 两套 runner 两个目录：`tests/*.test.js`（`node:test` / 自定义运行器，`npm test`、CI）与 `tests/unit/**/*.test.ts(x)`（jest，`npm run test:unit`），不能混。
- 覆盖率门禁是**运行期用例数精确对账**，不是行覆盖率；发现不了「用例过但分支没测」。
- 重数只能靠跑，不能数 `check(`/`test(` 调用点（运行期计数合法地大于调用点数）。
- 新增/删除测试文件时同一个改动里要更新：基线 JSON 的 `files`（对象映射，不是数组）+ `runnerFiles` + `backendTotal`/`runnerTotal`，再跑 `sync-doc-counts.js`。`nodeTestSuiteTotal` 只统计 `nodeTestSuiteFiles` 里的 7 个文件，不随新文件变化。
- `node --test` 每个文件是独立子进程；单文件失败只在该文件的 TAP 段里，别在汇总尾部找。
- 隔离自证：往 `server/data/` 播种哨兵内容 → 跑全量 → 校验文件字节不变（CI 有同名步骤）。

## 8. 已知坑（本仓库实际踩过）

1. **引用日志前先看时间戳**：`/tmp` 下常有同名历史日志，`ls --time-style=+%H:%M:%S` 确认是本轮再引用；不要拿上一轮的绿灯当本轮证据。
2. **Git Bash 的 `/tmp` ≠ Node 的 `/tmp`**：把 bash 路径传给 Node 脚本先用 `cygpath -w`。
3. **`git show <rev>:<path>` 在 Git Bash 会被路径转换破坏**：改用 `git ls-tree -r <rev> -- <path>` 取 blob 再 `git cat-file -p`。
4. **写文件工具对工作区外已存在文件会拒绝**：用 Edit 而不是 Write。
5. **Windows 上 `require('server/index.js')` 后直接退出会触发 libuv 断言**：需要 `Connection: close` + `closeAllConnections()` + `await server.close()`。
6. **事件写了却没落**：先查 `EVENT_TYPES` 与 `SAFE_PAYLOAD_KEYS`；数组字段会被 `safePayload` 丢掉（用逗号 join）。
7. **改 `scripts/api-capability-registry.json` 后**必须 `node scripts/verify-api-capabilities.js --write` 重生成 AGENTS 区块。
8. **`react-hooks/set-state-in-effect` 会被 lint 拦**：初始动作状态从 props 初始化，并把 `initialAction` 放进组件 `key`。
9. **台账状态列解析**：只认 `1/1.0/0.5/0/0.0`，括号里的日期与「判 1」不是状态；解析失败脚本抛错，属于预期行为。
